\chapter{Conclusion}
\label{chap:conclusion}

\section{Summary}

A camera-based location estimator for mountain terrain. Given one or more photographs, the system segments the sky, extracts a horizon profile, and matches it against a precomputed database. No satellite signal needed.

\section{Key Results}

\begin{itemize}
    \item \textbf{Synthetic:} 86.4\% of answered queries within 500\,m, median 135\,m.
    \item \textbf{Real-photo:} with consensus filtering, 85.7\% within 1\,km, median $\sim$40\,m.
    \item \textbf{Robustness:} stable up to 1.0$^\circ$ profile noise.
    \item \textbf{On-device:} 41\,MB model, 10.5\,MB database subset, $\sim$138\,MB peak RAM. No network needed.
\end{itemize}

\section{Limitations}

\begin{itemize}
    \item \textbf{DEM resolution:} At 30\,m, nearby viewpoints share similar profiles. Finer DEMs would reduce imposter matches.
    \item \textbf{Segmentation quality:} Real photos with haze, fog, or unusual lighting produce noisier masks. The consensus gate handles this by abstaining.
    \item \textbf{Narrow FOV:} Single-crop photos give ambiguous profiles. Multi-crop fusion (2--3 photos) substantially improves accuracy.
\end{itemize}

\section{Future Work}

\begin{itemize}
    \item \textbf{Finer DEMs:} Higher-resolution elevation data would reduce profile ambiguity.
    \item \textbf{Field testing:} Real hiking conditions with phone cameras and varying weather.
    \item \textbf{Other regions:} Test on different mountain ranges to check generalisation.
\end{itemize}
